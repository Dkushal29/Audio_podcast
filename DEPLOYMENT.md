# EchoSpace Production Deployment Guide (Vercel + Render + PostgreSQL + S3/R2)

This guide covers deploying **EchoSpace** to production with **Vercel** (React/Vite frontend), **Render** (Dockerized Node.js + Express + Socket.IO + FFmpeg backend), **Render PostgreSQL**, and **S3-compatible object storage** (Cloudflare R2, AWS S3, or Backblaze B2).

---

## 1. Prerequisites
- A GitHub repository containing the EchoSpace codebase (`main` branch).
- A **Vercel** account (for the frontend).
- A **Render** account (for the backend web service + PostgreSQL database).
- An **S3-compatible object storage** bucket (Cloudflare R2, AWS S3, or MinIO/B2) for persistent audio files.

---

## 2. Environment Variables Reference

### Frontend (Vercel — Public Build-Time Variables)
Never place backend secrets in `VITE_*` variables.
- `VITE_API_URL` — Full HTTPS base URL of the Render backend API (e.g. `https://echospace-backend.onrender.com/api`).
- `VITE_SOCKET_URL` — Full HTTPS/WSS origin of the Render backend (e.g. `https://echospace-backend.onrender.com`).

### Backend (Render — Secrets & Configuration)
- `NODE_ENV` — `production`
- `PORT` — `8080` (or Render's injected `PORT`)
- `DATABASE_URL` — PostgreSQL connection string from Render PostgreSQL (`?sslmode=require` if external).
- `JWT_SECRET` — Strong random secret (auto-generated by `render.yaml` or `openssl rand -hex 32`).
- `JWT_EXPIRES_IN` — `7d`
- `CORS_ORIGIN` — Comma-separated allowed frontend origins (e.g. `https://echospace.vercel.app`).
- `ALLOW_EXTENSION_CORS` — `true` (allows Chrome Extension `chrome-extension://` origins).
- `PUBLIC_BASE_URL` — Public HTTPS URL of the Render backend (e.g. `https://echospace-backend.onrender.com`).
- `STORAGE_DRIVER` — `s3` (required in production; ephemeral local disk is blocked unless `ALLOW_EPHEMERAL_STORAGE=true`).
- `MAX_FILE_SIZE_MB` — `100`
- `S3_ENDPOINT` — `https://t3.storage.dev` (Tigris) or S3-compatible endpoint.
- `S3_REGION` — `auto` (Tigris) or AWS region.
- `S3_BUCKET` — Private bucket name (e.g. `echospace.media`).
- `S3_ACCESS_KEY_ID` — Tigris / S3 access key ID.
- `S3_SECRET_ACCESS_KEY` — Tigris / S3 secret access key.
- `S3_FORCE_PATH_STYLE` — `false` (set `true` for MinIO or path-style S3 endpoints).
- `DEEPGRAM_API_KEY` — Backend-only Deepgram API key (never expose to Vercel/Vite).
- `DEEPGRAM_MODEL` — `nova-2` (default for lectures, podcasts, and diarization).

---

## 3. PostgreSQL Setup (Render)
1. `render.yaml` provisions `echospace-db` automatically via Render Blueprints, or create a PostgreSQL instance manually in the Render Dashboard.
2. Copy the **Internal Database URL** for the Render web service (`DATABASE_URL`).
3. Prisma automatically runs `npx prisma migrate deploy` on container startup (`backend/Dockerfile`).

---

## 4. Render Web Service Setup (Docker + FFmpeg)
1. Connect your GitHub repository in Render → **New +** → **Blueprint** (to use `render.yaml`), or **New Web Service**.
2. Runtime: **Docker** (`dockerfilePath: backend/Dockerfile`, `dockerContext: backend`).
3. Health Check Path: `/api/health` (Readiness endpoint also available at `/api/ready`).
4. The backend binds to `0.0.0.0:$PORT` and trusts the Render HTTPS proxy (`app.set('trust proxy', 1)`).

---

## 5. Background Worker & Queue Strategy
EchoSpace uses a **PostgreSQL-backed persistent `ImportJob` queue** (`backend/src/modules/imports/imports.worker.js`).
- Jobs are persisted in PostgreSQL (`QUEUED` → `VALIDATING` → `FETCHING` → `PROCESSING` → `UPLOADING` → `COMPLETED` / `FAILED` / `CANCELLED`).
- On startup, `recoverImportJobs()` automatically re-queues any interrupted jobs from a prior deploy or crash.
- Concurrency is capped (`MAX_CONCURRENT = 2`) inside the Render web service; no separate Redis/BullMQ service is required unless scaling beyond a single backend instance.

---

## 6. FFmpeg Installation & Configuration
`backend/Dockerfile` installs `ffmpeg` and `ffprobe` on `node:20-slim` via `apt-get`.
- `ffprobe` validates audio streams, extracts duration, and reads embedded title/artist tags.
- `ffmpeg` extracts/normalizes audio from supported containers when needed.

---

## 7. Object Storage Setup (S3 / Cloudflare R2)
1. Create a **private** bucket (no public read access needed; EchoSpace streams audio through authenticated `/api/episodes/:id/audio` and `/api/clips/:token/audio` endpoints with HTTP `206` Range support).
2. Create an API token/key pair with `PutObject`, `GetObject`, `HeadObject`, and `DeleteObject` permissions on that bucket.
3. Configure `STORAGE_DRIVER=s3` and the `S3_*` environment variables in Render.

---

## 8. Vercel Frontend Setup
1. Import the GitHub repository in Vercel (Root Directory: `.`).
2. Framework Preset: **Vite** (`npm run build`, Output Directory: `dist`).
3. `vercel.json` handles SPA client-side routing rewrites (`/(.*) -> /index.html`).

---

## 9. Frontend Environment Variables (Vercel)
Set in Vercel Project Settings → **Environment Variables**:
- `VITE_API_URL=https://<your-render-service>.onrender.com/api`
- `VITE_SOCKET_URL=https://<your-render-service>.onrender.com`

---

## 10. Backend Environment Variables (Render)
Set all secret variables in Render → Service → **Environment**, ensuring `CORS_ORIGIN` matches your exact Vercel production domain (`https://<your-app>.vercel.app`, no trailing slash).

---

## 11. CORS Configuration
- `backend/src/app.js` and `backend/src/sockets/index.js` both validate origins against `CORS_ORIGIN` (comma-separated list) and optionally `chrome-extension://*` when `ALLOW_EXTENSION_CORS=true`.
- `exposedHeaders` includes `Content-Range`, `Accept-Ranges`, and `Content-Length` for WaveSurfer range seeking.

---

## 12. Socket.IO Production Configuration
- Socket.IO runs on the same HTTP server as Express (`/socket.io`).
- Render supports WebSockets natively over HTTPS (`wss://`).
- Clients authenticate in the Socket.IO handshake using `auth: { token }`.

---

## 13. Prisma Migration Commands
- Local dev migration creation: `npx prisma migrate dev --name <name>`
- Production deployment (automated in `Dockerfile`): `npx prisma migrate deploy`
- Never run `prisma migrate reset` or `prisma db push --force-reset` in production.

---

## 14. First Deployment Procedure
1. Provision S3/R2 bucket and obtain credentials.
2. Deploy Render Blueprint (`render.yaml`) and fill in `CORS_ORIGIN`, `PUBLIC_BASE_URL`, and `S3_*` env vars.
3. Deploy Vercel frontend with `VITE_API_URL` and `VITE_SOCKET_URL` pointing to Render.
4. Update `CORS_ORIGIN` in Render if Vercel assigned a custom/preview domain, then redeploy Render.

---

## 15. Verification Checklist
- `GET https://<render-url>/api/health` returns `200` with `"database":"connected"`.
- `GET https://<render-url>/api/ready` returns `200` with `"storageDriver":"s3"`.
- Register a user, create a workspace, upload an MP3, and verify WaveSurfer playback + Range seeking.
- Test "Import from Link" with a public `.mp3` URL and verify stage progress + Audio Studio playback.
- Create an annotation, reply, and highlight clip; open `/clips/:token` in an incognito window.

---

## 16. Common Deployment Errors
- **CORS error on login**: `CORS_ORIGIN` in Render has a trailing slash or doesn't match the Vercel URL.
- **500 on audio upload**: Missing `S3_*` credentials or `STORAGE_DRIVER` not set to `s3`.
- **Database connection error**: `DATABASE_URL` missing or SSL required (`?sslmode=require`).

---

## 17. Redeployment Instructions
- Push to `main` (or trigger Manual Deploy in Render / Redeploy in Vercel).
- `Dockerfile` runs `npx prisma migrate deploy` before starting Node.

---

## 18. Rollback Guidance
- In Vercel: **Deployments** → select previous healthy deployment → **Promote to Production**.
- In Render: **Events / Deploys** → **Rollback** to previous image. Only apply forward-compatible Prisma migrations.

---

## 19. Storage & Database Backups
- Enable automated daily backups on Render PostgreSQL.
- Enable versioning or lifecycle policies on your S3/R2 bucket to protect against accidental deletion.

## 7. Smart Media Import v2

EchoSpace supports importing audio into private Tigris object storage (`STORAGE_DRIVER=s3`) and Neon PostgreSQL metadata:
- **Supported direct formats**: MP3, WAV, M4A, OGG, FLAC, AAC, WebM (including extensionless CDN URLs verified via magic-byte + `ffprobe` inspection).
- **Authorized video-to-audio extraction**: Direct `.mp4` / `.mov` / `.mkv` / `.webm` media files are probed and extracted to MP3 via FFmpeg in the worker (`EXTRACTING` stage).
- **Podcast discovery & batch import**: RSS/Atom feeds, Apple Podcasts URLs, and show pages with RSS auto-discovery (`POST /api/imports/rss/batch`).
- **Cloud files**: Public Google Drive, Dropbox, and OneDrive share links.
- **External-link mode**: YouTube, Vimeo, and Spotify links are stored as `EXTERNAL_LINK` collaboration sessions without downloading or rehosting media.
- **Unsupported streaming pages**: Music streaming webpages (e.g., Gaana, JioSaavn) are classified and rejected with clear guidance.
- **Security**: DNS-pinned SSRF protection (`backend/src/utils/ssrf.js`), 100 MB file-size limit, 4-hour duration limit, and `0004_import_v2` persistent `ImportJob` stages (`QUEUED`, `VALIDATING`, `FETCHING`, `DOWNLOADING`, `EXTRACTING`, `PROCESSING`, `UPLOADING`, `COMPLETED`, `FAILED`, `CANCELLED`).

## 8. EchoSpace Video Collaboration (YouTube → Workspace)

1. **Load the Chrome extension**: Open `chrome://extensions`, enable **Developer mode**, click **Load unpacked**, and select `extension/`.
2. **Configure endpoints (for production or custom ports)**: Open Extension **Options** (`extension/options.html`) and set **API Base URL** (e.g., `https://echospace-backend.onrender.com/api`) and **Web App URL** (e.g., `https://echospace.vercel.app`).
3. **Sign in**: Open the extension popup and sign in with your EchoSpace account.
4. **Watch YouTube**: Open any YouTube video (`youtube.com/watch?v=...` or `youtu.be/...`). The extension detects the video ID, canonical URL, title, channel name, thumbnail, and live playback timestamp (including YouTube SPA navigation).
5. **Collaborate**:
   - **Annotate**: Capture the exact playback timestamp and save a Study (`Question`, `Note`, `Insight`, `Revision`) or Creator (`Feedback`, `Correction`, `Suggestion`) note.
   - **Ask Question**: Post a timestamped question and notify workspace teammates (`QUESTION_ASKED`).
   - **Bookmark**: Save a timestamped bookmark (`POST /api/episodes/:id/bookmarks`).
   - **Share Moment**: Share the timestamped video moment with your workspace (`VIDEO_MOMENT_SHARED`) and notify members in real time via Socket.IO.
6. **Discuss in EchoSpace**: Click **View Video** or **Workspace** in the extension to open the collaborative video page (`/app/recordings/:id`), view the chronological timeline and bookmarks, reply to threads, and click any timestamp link (`https://www.youtube.com/watch?v=VIDEO_ID&t=272s`) to jump back to the exact moment on YouTube.
